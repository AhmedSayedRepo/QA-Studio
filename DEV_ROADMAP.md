## What this app is
Flet **0.85.3** (pinned) desktop app — an Azure DevOps test-case / test-plan generator. Core files:

- `main.py` (~7,260 lines) — `class QAStudio`: all screens, shell/nav, window chrome, dialogs, self-update, login gate.
- `engine.py` (`E`) — providers/config (`E.AI_CONFIG`), generation, `apply_update`.
- `regression.py` — Regression + Test-Plan screens; `_checkbox_multiselect` (the custom inline dropdown used on Setup too).
- `sprint_titles.py`, `users_screen.py`, `ai_usage_screen.py` — those screens.
- `theme.py` (`T`) — design tokens (`T.VIOLET`, `T.INK`, `T.R`, …) + `apply_theme`.
- `store.py` — DPAPI-encrypted creds (`store.load()` / `store.save(self.creds)`).
- `auth_supabase.py` (`auth`) — external auth gate + per-user permissions.
- `diag_log.py` — local-only diagnostic logging (rotating file, `~/.qa_tool/diagnostics.log`) for the app's many deliberate fail-soft `except` blocks.
- `idle_watch.py` — idle-timeout auto-logout (watchdog thread + countdown dialog); extracted from `main.py`, same pattern as `window_chrome.py`/`login.py`.
- `installer.py`, `install.bat`, `release.bat`, `_sync_to_install.py`.

## Session changes (2026-07-11) — Automation Activity panel overhaul
Follows directly on the panel-blank saga (#69–79 above, which fixed the right-side rail rendering nothing). This session's work was all live-log quality/readability, driven by real run screenshots and raw log pastes from the user:
- **Rail trimmed at the bottom + log not copyable** — the log `Container` had a fixed `height=460` (cut off short of the rail's actual bottom) and `app._auto_log_col` was an `ft.ListView` (doesn't register with Flutter's ambient `SelectionArea`, so drag-select/Ctrl+C silently did nothing). Fixed: `height=460` → `expand=True`; `ListView` reverted to `ft.Column(scroll=ft.ScrollMode.AUTO, expand=True)` (matches `run.py`/`report.py`'s already-working panels) — but Column has no built-in auto-scroll-to-bottom, so added `_auto_log_scroll_end(col)` (`col.scroll_to(offset=10_000_000, duration=100)`) called after every append.
- **Count cards restyled to match Run's `stat_tile`** — `_auto_counts_header()` rebuilt by hand (not calling `stat_tile()` directly, so `self._auto_count_ctl[key]` keeps a live handle to the number `ft.Text` for in-place updates) to use the same neutral-card + gradient-number look as Run's stat tiles instead of the old solid-tinted pill.
- **Symbols instead of bullets, then tightened spacing** — `dim`-tone lines got a small chevron (`›`) instead of a plain gray dot; a follow-up screenshot showed the icon sitting too far from the text, fixed by narrowing `sym_wrap` (`width=16, alignment=CENTER` → `width=13, alignment=CENTER_RIGHT`).
- **Missing case titles for cases 3–N in a concurrent run** — `_compile_one` runs on `_COMPILE_WORKERS=2` threads; progress lines ("Sequencing case k/N") are submitted eagerly upfront, but each case's title/heartbeat logs whenever ITS worker actually finishes — out of order. Self-labeled every title AND heartbeat line with its own `#k/N` tag so each line is individually identifiable regardless of arrival order.
- **RTL/LTR bidi scrambling of the `#k/N` tag** — Flutter's `Text` resolves paragraph direction from the first strong-directional character in the WHOLE string, so concatenating an LTR tag next to Arabic text scrambled the tag itself (`"#3/36"` rendered back as `"3/36#"`) regardless of which end it was placed on (a first attempt at moving the tag to the other end only relocated the bug — confirmed insufficient via a later screenshot still showing `"19/36#"`). Real fix: stopped concatenating entirely — `engine.py` now joins "meta" (elapsed time + tag) and "body" (title) with an invisible `"\x1f"` (Unit Separator) delimiter, and `main.py`'s `_auto_log_line` splits on it, rendering meta and body as two INDEPENDENT `ft.Text` controls (each resolves bidi direction from only its own content, so neither can reorder relative to the other). Verified via `xxd` hex-dump that the raw `0x1f` byte is actually present in both files (it's invisible in a normal Read/grep view — looks like an empty string at a glance).
- **Random-looking interleaving of title + heartbeat lines** — merged into ONE combined line per case (`"  ⏱ 0:20 · #3/36\x1fCase title here"`, tone `"case"`, its own bright-cyan color distinct from `"dim"`/`"story"`), logged once at actual completion instead of two separate calls at different times.
- **"Logs not appearing on time" — clearing then stopping a run a few seconds later dumped a big batch of lines at once** — every `_auto_logmsg` call independently spawned its own `page.run_thread(upd)` (no ordering guarantee); under heavy concurrent worker activity, especially the burst of in-flight calls finishing together on Stop, dozens could race/queue and paint as one batch. Fixed with an `_auto_log_upd_pending` coalescing flag: a call returns immediately if an update is already pending, and the flag clears (under the same lock) once `upd()` actually runs.
- **Repeated retry lines cluttering the log** — a regex (`^(.*?)\s*—\s*waiting \d+s then retry \(\d+/\d+\)…$`) collapses a new retry message in place over the previous one when its base text matches, instead of appending a fresh line per attempt.
- **"Does these cases really non-automatable?" — investigated and confirmed: no.** The log's "skipping non-automatable case (no actions)" lines were directly preceded by "compile failed (NVIDIA: rate limited (429)…) — using raw steps" — the AI-based compiler (`compile_test_case`) kept failing from an external, transient rate limit, forcing a fallback to `_intents_from_raw_steps` (a much weaker heuristic parser) that couldn't extract clear action/assertion verbs from validation-style steps (e.g. "ID number must be ≥10 digits, shows an error") even though they're clearly automatable in principle.
- **Fix: flag distinctly instead of silently skipping (`engine.py` `_compile_one`, ~line 8584).** Previously, when BOTH the AI compiler and the raw-steps fallback found zero actions and zero assertions, a non-`"presence"`-type case was dropped entirely (`return {"skip": True, ...}`) — indistinguishable from a genuinely non-automatable case. Now: the same best-effort visibility-check assertion `"presence"` cases already synthesize is generated for ANY case landing here, the case is KEPT (`case_dict["needs_review"] = True`), and a distinct `tone="review"` log line fires ("needs review — AI compile unavailable, placeholder check only · #k/N"). Wired a real `"review"` tone into `main.py`'s `_auto_log_line` (amber, a flag glyph `⚑` — distinct from `"warn"`'s `⚠`) and into `generate_selfhealing_test_class`'s Java codegen (`engine.py` ~line 9415), which now emits a `// NEEDS REVIEW: ...` comment directly above any flagged case's generated test method, so it's visible in the actual output file, not just the live log.
- **Bash-sandbox verification note (recurring):** this session again saw the bash mount's `ast.parse`/`tail` disagree with direct `Read`-tool contents (a whole-file `ast.parse` flagged two "unterminated string literal" errors at lines unrelated to any edit; `Read` at both exact lines showed valid, unrelated code — same stale-mount pattern documented earlier in this file). Verified the three actually-edited regions instead via function-bounded extraction (`_compile_one`, `generate_selfhealing_test_class`, `_auto_log_line`) — all parse clean. As always: don't trust a whole-file bash syntax check in this sandbox: verify the specific edited region directly.

## Gotchas (learned the hard way)
- **Never** copy/modify large files (`main.py`, `regression.py`, `engine.py`) via shell `cp`/`sed -i` on mounted folders — it can silently truncate. Use the Read/Edit/Write tools (host) or `_sync_to_install.py`.
- Flet 0.85 specifics: async window methods (`window.center()`/`destroy()` are coroutines), `HoverEvent.local_position` (Offset `.x`/`.y`, not `local_x`), `page.window.title_bar_hidden` for frameless.
- Class-level attributes (`HELP`, `PROVIDER_KEY_HELP`) sit between methods in `main.py` — mind them when moving code.
